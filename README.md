# EduSport Manager — إدارة ومتابعة التلاميذ

تطبيق Flutter + Supabase لأستاذ التربية البدنية والرياضية، لإدارة الأقسام
والتلاميذ والحصص والحضور والتقييم والتحفيز — مبني حول فكرة **الاستخدام
الفعلي أثناء الحصة** (لمسة واحدة، بدون نماذج معقّدة، يعمل حتى بلا اتصال).

## الرؤية المعمارية (لماذا صُمِّم هكذا)

- **نظام تقييم واحد موحّد** (`evaluations` + `evaluation_criteria`) بفئات
  ثلاث (أكاديمي / بدني / سلوكي) بدل ثلاثة أنظمة متوازية متكررة.
- **"الحصة الآن"** هي الشاشة المركزية: حضور بلمسة واحدة + نقاط تحفيزية
  سريعة، منفصلان عن الإدخال التفصيلي (تقييمات، تعديل قواعد) الذي يُنجَز
  لاحقًا من المكتب.
- **الشارات تُمنح تلقائيًا** حين يمكن حسابها من البيانات (حضور مثالي، نشاط
  عالٍ)، وتبقى الشارات التقديرية (روح الفريق، نجم الشهر) يدوية بالكامل.
- **وضع عدم اتصال بسيط وحقيقي**: العمليات الحرجة (الحضور، النقاط) تُخزَّن
  محليًا عند فشل الشبكة وتُزامَن تلقائيًا عند عودتها — أساسي لواقع الملعب.
- **لوحة التحكم تبدأ بقرار لا برقم**: "من يحتاج انتباهك؟" (غياب متكرر)
  تظهر قبل الإحصائيات العامة.
- **بطاقة اللاعب**: هوية بصرية رياضية للتلميذ بدل صف بيانات جاف.

## حالة المشروع

✅ **مكتمل وقابل للتشغيل**: تسجيل الدخول، لوحة التحكم، الأقسام، التلاميذ،
الحصص (إنشاء/تعديل/حذف)، "الحصة الآن" (حضور + نقاط سريعة، مع طابور مزامنة
عند انقطاع الشبكة)، نظام التقييم الموحّد (معايير قابلة للإضافة/التعديل/
الحذف بالكامل، تقييم جماعي للقسم، متوسطات لكل معيار وللقسم وللتلميذ بثلاث
فئات)، قواعد النقاط التحفيزية (قابلة للتعديل)، الشارات (يدوية + تلقائية)،
ملف تلميذ شامل (حضور، تقييم، نقاط، شارات، سجل زمني موحّد)، محرك شارات
تلقائي.

⏳ **لم يُبنَ بعد** (البنية جاهزة لاستقباله دون إعادة هيكلة): التقارير
القابلة للتصدير PDF/Excel، الرسوم البيانية التفصيلية (fl_chart مُدرَجة في
pubspec وجاهزة)، استيراد التلاميذ من Excel/CSV، رفع صور التلاميذ (image_picker
مُدرَجة وجاهزة)، حسابات أولياء الأمور، الإشعارات.

## بنية المجلدات

```
lib/
  core/            # ثوابت، ثيم
  models/          # Teacher, Section, Student, SessionModel, AttendanceRecord,
                     EvaluationCriterion/Evaluation (نظام موحّد), MotivationRule/
                     MotivationPoint, AchievementBadge/StudentBadge
  services/        # Supabase client، المصادقة، تهيئة افتراضية، محرك الشارات،
                     طابور المزامنة دون اتصال
  repositories/     # طبقة CRUD لكل وحدة (قسم/تلميذ/حصة/حضور/تقييم/تحفيز/شارات/لوحة تحكم)
  providers/        # إدارة الحالة (الجلسة، السنة الدراسية المختارة)
  screens/          # auth, dashboard, sections, students, sessions, evaluations,
                     motivation, badges
  widgets/          # StatCard، AppDrawer، PlayerCard (بطاقة اللاعب)
supabase/
  schema.sql            # قاعدة البيانات الكاملة — نفّذها إن كنت تبدأ من الصفر
  phase3_migration.sql  # فقط إن كنت شغّلت نسخة قديمة من schema.sql سابقًا
```

### ملاحظة تسمية مهمة
صنف الشارة في الكود اسمه `AchievementBadge` وليس `Badge`، لتفادي تعارض
حقيقي مع ودجت `Badge` المدمج في Flutter (`material.dart`) — استخدام الاسم
`Badge` هنا كان سيسبب خطأ ترجمة (compile error) في أي ملف يستورد الاثنين
معًا. اسم الجدول في قاعدة البيانات لا يزال `badges` (لا علاقة له بهذا).

## خطوات التشغيل

1. **Supabase**
   - أنشئ مشروعًا على supabase.com (أو استخدم مشروعك الحالي).
   - **إن كنت تبدأ من الصفر**: نفّذ `supabase/schema.sql` كاملاً في SQL Editor.
   - **إن كنت قد شغّلت نسخة قديمة من المرحلة الأولى/الثانية سابقًا**: نفّذ
     `supabase/phase3_migration.sql` بدلاً من ذلك (يرحّل بياناتك القديمة دون فقدانها).
   - فعّل تسجيل الدخول بالبريد الإلكتروني في Authentication > Providers.

2. **ربط التطبيق**
   - افتح `lib/core/constants/app_constants.dart` وضع `url` و `anonKey`
     الخاصين بمشروعك (Project Settings > API).

3. **التشغيل محليًا**
   ```bash
   flutter pub get
   flutter analyze
   flutter run
   ```

## بناء APK للأندرويد

```bash
# 1. تثبيت الحزم
flutter pub get

# 2. فحص الأخطاء (مهم قبل البناء)
flutter analyze

# 3. بناء نسخة تجريبية (سريعة، للتجربة الفورية على جهازك)
flutter build apk --debug

# 4. أو نسخة إنتاجية (أصغر حجمًا، تتطلب مفتاح توقيع لاحقًا للنشر على المتجر)
flutter build apk --release

# الناتج:
# build/app/outputs/flutter-apk/app-debug.apk
# build/app/outputs/flutter-apk/app-release.apk

# للتثبيت المباشر على جهاز متصل عبر USB:
flutter install
```

## ملاحظة صريحة حول ما لم أستطع فعله هنا

بيئة العمل الحالية لا تحتوي Flutter SDK ولا اتصال إنترنت (محجوب صراحةً)،
لذا لم أستطع تشغيل `flutter analyze` أو `flutter test` أو بناء الـ APK
فعليًا من هذه الجلسة. بدلاً من ذلك، أجريت مراجعة يدوية شاملة للمشروع بعد
كل تعديل: تحققت برمجيًا من أن كل الاستيرادات النسبية (42 ملف Dart) تُحل
بشكل صحيح، لا توجد أصناف مكررة، الأقواس متوازنة في كل ملف، كل الحزم
المستوردة معرَّفة في `pubspec.yaml`، وكل مسارات `context.push/go` تطابق
مسارات `GoRouter` المعرَّفة. وجدت وأصلحت خلال هذه المراجعة خطأين حقيقيين
كانا سيوقفان الترجمة (استعلام `dashboard_repository.dart` كان لا يزال
يشير لجدول `grades` القديم، وتعارض اسم الصنف `Badge` مع ودجت Flutter).

هذا لا يغني عن `flutter analyze` الفعلي على جهازك — قد تظهر أخطاء توافق
إصدارات حزم لم أستطع اكتشافها يدويًا. إن ظهر أي خطأ، أرسل لي نص الخطأ
كاملاً وسأصلحه فورًا.
